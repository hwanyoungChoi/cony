# cony

Claude Code용 개인 플러그인 마켓플레이스. 기획 / 클라이언트 / 백엔드 / 테스트 4인 에이전트 팀이 스스로 토론하고 작업한 뒤 보고하는 하네스, `cony` 플러그인이 들어 있다.

## 설치

```bash
claude plugin marketplace add hwanyoungChoi/cony
claude plugin install cony@conychoi-plugins
```

## 사용

```
/cony:setup                       # 새 프로젝트에 하네스 깔기 (한 번)
/cony:team 프로필 사진 업로드 기능   # 목표만 주면 팀이 알아서 끝까지
/cony:status                      # 언제든 중간보고 (다른 세션에서도 됨)
```

진행 상황은 `.cony/board.md`를 직접 열어봐도 된다.

## 하네스 구성

| 요소 | 질문 | cony가 갖춘 것 |
|---|---|---|
| 컨텍스트 | 무엇을 알고 시작하는가 | `CLAUDE.md` 작업 원칙, `CONVENTIONS.md`, 스펙, 결정 기록, 세션 시작 시 보드 자동 주입 |
| 도구 | 무엇을 할 수 있는가 | 역할별 에이전트 4명, 브라우저·시뮬레이터 화면 확인, 검증 명령 권한 허용 목록 |
| 제약 | 무엇을 못 하게 막는가 | hook: 지침 파일 수정은 승인 필요, `--no-verify`·`--amend`·force push 차단, push·`reset --hard`·DB 리셋은 승인 필요 |
| 피드백 루프 | 틀렸다는 걸 어떻게 아는가 | hook: 파일 수정 즉시 ESLint, 종료 전 lint + typecheck(실패하면 못 끝냄), 커밋 전 husky, tester의 독립 검증 |
| 흐름 | 어떤 순서로 일하는가 | `/cony:team`: 기획 → 스펙 토론 → 태스크별 개발·화면 확인·테스트 → 보고 |
| 개선 | 실수가 어떻게 규칙이 되는가 | `log.md`의 `되돌림`·`놓침` → 보고서의 "규칙 제안" → 사람이 `CLAUDE.md`나 hook으로 승격 |

hook은 `.cony/` 디렉토리가 있는 프로젝트에서만 동작한다. 다른 프로젝트에는 영향이 없다.

## 팀

| 에이전트 | 만들 때 | 검토할 때 보는 것 |
|---|---|---|
| `planner` | 스펙, 태스크, 선택지 | 요구사항, 범위 |
| `backend-dev` | DB, 마이그레이션, API | 데이터 무결성, 보안, API 계약 |
| `client-dev` | 화면, API 연동 | 화면 흐름, 사용성 |
| `tester` | 테스트 작성·실행 | 테스트 가능성 |

에이전트끼리는 직접 대화하지 못한다. 메인 세션이 리드가 되어 의견을 전달하며 토론을 진행한다.

1. **제안**: 담당자가 선택지 2~3개와 추천
2. **검토**: 다른 역할들이 병렬로 찬성/반대와 근거
3. **반론**: 이견이 있으면 제안자가 1회 응답
4. **결정**: 리드가 근거로 판정 (CLAUDE.md 제약 → 작업 원칙 → 테스트 가능성 → 되돌리기 쉬운 쪽)
5. **기록**: `.cony/decisions/NNN-*.md`

사용자에게는 되돌릴 수 없는 일(push, 배포, 데이터 삭제, 유료 서비스), 지침 파일 변경, 제품 목표가 갈리는 해석일 때만 묻는다.

## 작업 공간 `.cony/`

| 경로 | 내용 |
|---|---|
| `board.md` | 현황판. 리드가 단계마다 갱신 |
| `specs/` | 스펙과 태스크 |
| `decisions/` | 토론 기록 (ADR) |
| `log.md` | 작업 기록 (`요청` / `토론` / `AI` / `되돌림` / `놓침`) |
| `reports/` | 최종 보고서 |
| `.cache/` | hook 상태 (gitignore) |
