# cony 중간보고

파일을 읽기만 한다. 아무것도 수정하지 않는다. 리드 세션에 재개 메시지를 보내는 것은 사용자가 확인했을 때만 한다.

## 절차

1. `.cony/board.md`를 읽는다. 없으면 "진행 중인 cony 작업이 없습니다"라고 답하고 끝낸다.
2. 아래도 함께 읽는다.
   - `.cony/decisions/`의 최근 결정 3개
   - `.cony/log.md`의 마지막 태스크 항목
   - `git status --short`와 `git diff --stat`
   - board에 PR 링크가 있으면 `gh pr view {링크} --json state,mergedAt` 과 `gh pr checks {링크}`
3. **리드 세션 확인** (데스크톱 앱의 세션 관리 도구 `get_session`, `list_sessions`, 메시지 보내기가 있을 때만. 없으면 건너뛴다)
   - 보드 끝의 `<!-- lead: local_... -->`에서 리드 세션 ID를 읽고 `get_session`으로 상태(실행 중인지, 마지막 활동 시각, 제목)를 본다.
   - 기록이 없거나 그 세션을 찾을 수 없으면 `list_sessions`에서 작업 폴더가 이 프로젝트(또는 그 아래)인 세션을 찾는다. 지금 세션은 뺀다. 하나면 그 세션으로 보고, 여럿이면 제목과 마지막 활동 시각을 보여주고 사용자에게 고르게 한다.
   - 보드 상태가 "진행 중"이나 "중단됨"인데 리드 세션이 실행 중이 아니면 멈춘 것이다. 보고 맨 위에 "리드 [제목]이 {시각}부터 멈춰 있다"고 알리고 **이어서 하게 할지 묻는다.**
   - 사용자가 원하면 그 세션에 아래 메시지를 보낸다.
     > 사용자 확인을 받은 cony 재개 요청입니다. `.cony/board.md`와 `.cony/log.md` 마지막 항목을 읽고 `/cony:team` 절차대로 멈춘 지점부터 이어서 진행하세요. 시작할 때 `board.mjs --status "진행 중" --lead <자기 세션 ID>`로 보드를 되돌리세요.
4. 보고한다.

## 보고 형식

```
{목표} · {상태} · TODO {n} · PROGRESS {n} · REVIEW {n} · DONE {n} (백로그 {n})
마지막 업데이트: {시각} ({N분 전})

지금: {지금 하는 일}
최근 결정: {ADR 제목들, 한 줄씩}
확인 필요: {사용자 확인 필요 항목 또는 "없음"}
막힌 것: {없으면 "없음"}
변경 중인 파일: {diff stat 요약}
리드 세션: {제목} · {실행 중 / 멈춤 (마지막 활동 시각)} (확인할 수 없으면 줄을 뺀다)
PR: {링크} · CI {통과/진행 중/실패} · {열림/머지됨}
```

- 마지막 업데이트가 30분 넘게 지났는데 상태가 "진행 중"이면, 리드 세션이 멈췄을 수 있다고 알린다.
- 상태가 "중단됨"이면 리드 세션이 끝난 것이다. `/cony:team 이어서`로 다시 시작할 수 있다고 알린다.
- "사용자 확인 필요"가 있으면 맨 위로 올려서 강조한다.
